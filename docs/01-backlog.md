# Product Backlog — เว็บ Todo List

## เป้าหมายของผลิตภัณฑ์
เว็บแอป Todo List ที่ใช้งานง่าย ช่วยให้ผู้ใช้จดบันทึกสิ่งที่ต้องทำ เพิ่ม ลบ และทำเครื่องหมายว่าเสร็จแล้วได้ โดยข้อมูลถูกเก็บใน localStorage ของเบราว์เซอร์ ทำให้รายการคงอยู่หลังปิด/เปิดหน้าเว็บใหม่ โดยไม่ต้องมี backend หรือระบบสมาชิก

## ผู้ใช้เป้าหมาย
- ผู้ใช้ทั่วไปที่ต้องการจดบันทึกสิ่งที่ต้องทำในชีวิตประจำวัน (personal to-do)
- ผู้ใช้ที่ต้องการเครื่องมือง่าย ๆ ไม่ต้องลงทะเบียน ไม่ต้องตั้งค่าอะไร

## ข้อจำกัดของผลิตภัณฑ์ (Constraints)
- ไม่มี backend / ไม่มี server — ทำงานฝั่ง client ทั้งหมด
- ไม่มีระบบ user account / ไม่มี login
- ข้อมูลถูกเก็บเฉพาะใน localStorage ของเบราว์เซอร์บนเครื่องนั้น ๆ — ไม่ sync ข้ามอุปกรณ์ และหายได้ถ้าผู้ใช้ล้างข้อมูลเบราว์เซอร์

## Backlog

### US-001 — เพิ่มรายการ todo (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการเพิ่มรายการสิ่งที่ต้องทำใหม่ เพื่อจดบันทึกงานที่ต้องทำ

Acceptance Criteria:
1. ผู้ใช้พิมพ์ข้อความในช่อง input แล้วกดปุ่มเพิ่ม (หรือกด Enter) รายการใหม่ปรากฏใน list ทันที
2. รายการใหม่มีสถานะเริ่มต้นเป็น "ยังไม่เสร็จ"
3. ถ้ากดเพิ่มโดยช่อง input ว่าง หรือมีแต่ช่องว่าง (whitespace) ระบบต้องไม่เพิ่มรายการ และแสดงข้อความ/สัญญาณบอกผู้ใช้ (เช่น shake หรือข้อความแจ้ง)
4. รายการที่เพิ่มถูกบันทึกลง localStorage ทันที

### US-002 — ลบรายการ (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการลบรายการที่ไม่ต้องการแล้ว เพื่อให้ list มีเฉพาะงานที่ยังต้องทำ

Acceptance Criteria:
1. ทุกรายการใน list มีปุ่มลบที่มองเห็นได้ชัดเจน
2. กดปุ่มลบแล้วรายการนั้นหายไปจาก list ทันที
3. รายการที่ถูกลบถูกลบออกจาก localStorage ด้วย (หลัง refresh รายการนั้นไม่กลับมา)
4. การลบรายการหนึ่งไม่กระทบรายการอื่น

### US-003 — ติ๊กทำเคราะห์หมายว่าเสร็จแล้ว (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการติ๊กเครื่องหมายว่ารายการใดเสร็จแล้ว เพื่อแยกให้เห็นว่างานไหนเสร็จ/ยังไม่เสร็จ

Acceptance Criteria:
1. ทุกรายการมี checkbox ที่คลิกได้
2. ติ๊กแล้วรายการแสดงสถานะ "เสร็จแล้ว" ชัดเจน (เช่น ขีดฆ่าข้อความ, เปลี่ยนสี)
3. ติ๊กซ้ำ (uncheck) เพื่อเปลี่ยนกลับเป็น "ยังไม่เสร็จ" ได้
4. สถานะที่เปลี่ยนถูกบันทึกลง localStorage ทันที และคงอยู่หลัง refresh

### US-004 — ข้อมูลคงอยู่หลัง refresh ผ่าน localStorage (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการให้รายการทั้งหมด (ข้อความ + สถานะ) คงอยู่หลังปิดหรือ refresh หน้าเว็บ เพื่อไม่ต้องพิมพ์ใหม่ทุกครั้ง

Acceptance Criteria:
1. เปิดหน้าเว็บใหม่ (refresh / ปิดแล้วเปิด browser ใหม่) ระบบโหลดรายการทั้งหมดจาก localStorage มาแสดงพร้อมสถานะเดิมถูกต้อง
2. ลำดับรายการคงเดิมตามที่ผู้ใช้เพิ่มไว้
3. ถ้ายังไม่มีข้อมูลใน localStorage (ครั้งแรก) แสดงสถานะว่างที่เข้าใจง่าย (เช่น "ยังไม่มีรายการ") ไม่แสดง error
4. ถ้า localStorage มีข้อมูลที่เสียหาย/อ่านไม่ได้ ระบบต้องไม่ crash — แสดงสถานะว่างและทำงานต่อได้

### US-005 — แก้ไขข้อความรายการ (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการแก้ไขข้อความของรายการที่มีอยู่แล้ว เพื่อแก้ typo หรือปรับเนื้อหาโดยไม่ต้องลบแล้วเพิ่มใหม่

Acceptance Criteria:
1. ผู้ใช้สามารถเข้าโหมดแก้ไขข้อความของรายการได้ (เช่น ปุ่ม edit หรือ double-click)
2. บันทึกการแก้ไขแล้ว ข้อความใหม่แสดงใน list และบันทึกลง localStorage
3. ข้อความแก้ไขเป็นค่าว่าง/whitespace ไม่ได้ — ต้องมีการตรวจสอบเหมือน US-001
4. มีวิธียกเลิกการแก้ไขโดยไม่เปลี่ยนข้อความเดิม (เช่น กด Esc)

### US-006 — ลบรายการทั้งหมดที่เสร็จแล้ว (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการลบรายการที่ติ๊กว่าเสร็จแล้วทั้งหมดในครั้งเดียว เพื่อเคลียร์ list เร็วขึ้น

Acceptance Criteria:
1. มีปุ่ม "ลบรายการที่เสร็จแล้ว" ที่ใช้ได้เมื่อมีรายการสถานะเสร็จอย่างน้อย 1 รายการ
2. กดแล้วรายการที่เสร็จทั้งหมดหายไป รายการที่ยังไม่เสร็จคงอยู่ครบถ้วน
3. ผลลัพธ์ถูกบันทึกลง localStorage ทันที
4. ถ้าไม่มีรายการที่เสร็จ ปุ่มต้อง disabled หรือซ่อนไว้

### US-007 — นับจำนวนรายการค้าง/เสร็จ (Priority: Must)
ในฐานะผู้ใช้ ฉันต้องการเห็นจำนวนรายการที่ยังไม่เสร็จ (และ/หรือที่เสร็จแล้ว) เพื่อรู้ภาพรวมความคืบหน้า

Acceptance Criteria:
1. แสดงตัวเลขรายการที่ยังไม่เสร็จอย่างน้อย 1 ตัวเลข อัปเดตทันทีเมื่อเพิ่ม/ลบ/ติ๊ก
2. ตัวเลขถูกต้องตรงกับรายการใน list ทุกสถานการณ์ (รวมหลัง refresh)
3. ถ้าไม่มีรายการเลย แสดงค่า 0 หรือซ่อนส่วนนับได้

## นอกขอบเขต (Out of Scope)
- Backend, database, API ใด ๆ
- ระบบสมาชิก / login / โปรไฟล์ผู้ใช้
- การ sync ข้อมูลข้ามอุปกรณ์หรือข้ามเบราว์เซอร์
- การแชร์ todo ให้ผู้อื่น / การทำงานร่วมกัน (collaboration)
- Due date, reminder, การแจ้งเตือน, tag/category, การจัดเรียงลำดับด้วย drag-and-drop
- การทำงานแบบ offline-first ขั้นสูง (PWA install) — นอกเหนือจากที่ localStorage ให้อยู่แล้ว
- Filter แสดงเฉพาะรายการ "ยังไม่เสร็จ" หรือ "เสร็จแล้ว" — ผู้ใช้ยืนยันแล้วว่าไม่ทำ

## ข้อกำหนดของผลิตภัณฑ์ (Product Requirements)
- UI ต้องรองรับทั้งภาษาไทยและอังกฤษแบบ hybrid (เช่น ป้ายกำกับ/label แสดงสองภาษาคู่กัน) — รายละเอียดการนำเสนอเป็นหน้าที่ของ ux

## การตัดสินใจที่ยืนยันแล้ว (Confirmed Decisions)
1. ฟีเจอร์เสริม US-005 (แก้ไขข้อความ), US-006 (ลบรายการที่เสร็จแล้วทั้งหมด), US-007 (นับจำนวนค้าง/เสร็จ) — ผู้ใช้ยืนยันให้ทำทั้งหมด เปลี่ยน priority เป็น Must ทุกรายการ
2. Filter (แสดงเฉพาะยังไม่เสร็จ/เสร็จแล้ว) — ผู้ใช้ยืนยันไม่ทำ จัดเป็น Out of Scope
3. UI ต้องรองรับทั้งภาษาไทยและอังกฤษแบบ hybrid (เช่น ป้ายกำกับสองภาษา) — บันทึกเป็น requirement ของผลิตภัณฑ์
4. จำนวนรายการสูงสุด — ผู้ใช้ไม่มีข้อกำหนด ใช้ localStorage ปกติ ไม่ต้องจำกัดจำนวนรายการ
